# 网站归集桌面应用 — UX 优化设计方案

## 背景与目标

当前应用（Tauri 2 + Vue 3 + Rust）功能可用，但交互细节未达到"大厂级"流畅度：右键/滚动行为异常、侧栏长列表相互挤压、缺树形全局展开、标签输入原始，且存在回收站无确认、无校验等安全/数据隐患。

本次目标：在**不改变核心功能与后端逻辑**的前提下，集中修复这些交互与体验问题，使日常使用顺滑、安全、可预期。

## 范围

**纳入（本次必做）：**
- 用户提出的 4 项：批量栏吸顶、侧栏分区滚动、树形展开/收起全部、标签 chip 选择器
- 额外发现并确认的 P0/P1：
  - 回收站"彻底删除 / 清空"二次确认
  - 添加 / 编辑表单校验（必填 + URL 格式）
  - 空状态文案区分（全局空 vs 筛选无结果）
  - 表头点击排序
  - 列表键盘流（Delete / Ctrl+A / ↑↓ / Enter）
  - 批量"添加标签"弹窗与单条添加保持一致的标签选择器

**不纳入（本次不做，P2 打磨项）：**
- 弹窗自动聚焦首个输入框、搜索框快捷键聚焦、更显眼的 toast 提示、空库引导增强、列表虚拟滚动（上千条性能）、完整无障碍 ARIA

## 详细需求与验收标准

### 1. 批量操作栏吸顶（原问题 1）
- **现状**：选中网站后顶部出现"已选 N 项 / 检测 / 移动 / 删除…"工具条；长列表向下滚动时该工具条被推到可视区外。
- **方案**：该工具条改为 `position: sticky`（钉在列表容器顶部）。滚动时长列表内容在其下方滚动，工具条始终可见且可操作。
- **验收**：在"全部"视图选中若干项后滚动列表，工具条保持可见、按钮可用。

### 2. 侧栏分区（原问题 2）
- **现状**：侧栏整块 `overflow:auto`，分类过长时"视图 / 标签 / 系统"被推到可视区之外。
- **方案**：
  - 上区 = "分类"树，拥有独立滚动条；
  - 下区 = "视图(失效) / 标签 / 系统(回收站)"钉在侧栏底部，始终可见；
  - 下区内部："失效"钉顶、"回收站"钉底、"标签"列表设最大高度并独立滚动（标签极多时仅标签区内部滚动，不挤压其他）。
- **验收**：分类极多时，失效 / 标签 / 回收站始终可见；标签极多时仅标签区内部滚动。

### 3. 树形展开 / 收起全部（原问题 3）
- **方案**：在"分类"分组标题行右侧增加"展开全部 · 收起全部"两个小按钮。
  - 收起全部：仅留顶层分类（所有子分类收起）；
  - 展开全部：展开到最深层（当前最多 3 层：顶层 / 子分类 / 子子分类）；
  - 状态沿用现有 `settings.collapsedCategories` 机制，刷新后保持。
- **验收**：点击后整棵树展开 / 收起符合预期；刷新后保持上次状态。

### 4. 标签 chip 选择器（原问题 4 + 一致性）
- **单条添加 / 编辑（`AddEditModal`）**：
  - 已选标签显示为可删除的小方块（带 ×）；
  - 点击输入框弹出已有标签下拉，边打边筛，点选即加入已选；
  - 输入一个不存在的标签并按回车 = 新建；
  - 大小写不敏感去重（避免"工具"与"工具"变成两个）；
  - 新建标签自动进入全局标签池（侧栏"标签"区随后可见、可用于筛选）。
- **批量"添加标签"弹窗（`AddTagsModal`）**：复用同一选择器，保持体验一致。
- **验收**：两处入口体验一致；输入"工具"不会生成第二个"工具"；新建标签出现在侧栏标签区。

### 5. 回收站删除二次确认（P0）
- **现状**：`RecycleView` 的"彻底删除所选""清空回收站"直接永久删除，无任何确认。
- **方案**：复用现有 `ConfirmModal` 组件，删除前弹出确认框（清空回收站使用更醒目的文案与风险提示）。
- **验收**：点击彻底删除 / 清空回收站时先弹确认；确认后执行；取消则数据不动。

### 6. 添加 / 编辑校验（P0）
- **方案**：`AddEditModal` 保存前校验——名称非空、链接非空且为合法 URL（仅 `http` / `https`）；不合法时在对应字段下方内联提示，且不关闭弹窗。
- **验收**：名称空 / 链接空 / 非法链接均被拦截并提示，不会写入脏数据。

### 7. 空状态文案修正（P1）
- **方案**：`SiteTable` 无结果时区分两种情况：
  - 全局确实无网站 → 维持现有"还没有网站 / 点击右上角添加"引导；
  - 当前分类 / 标签 / 搜索筛选无结果 → 改为"当前筛选没有结果"。
- **验收**：切到空分类显示"当前筛选没有结果"；全局为空仍显示原引导。

### 8. 表头排序（P1）
- **方案**：点击"名称 / 链接 / 生命"等表头切换排序（升序 / 降序 / 无），排序状态存于 store，作用于 `filteredSites` 的输出顺序。
- **验收**：点击表头后列表按该列排序；再次点击切换方向；与搜索 / 分类筛选叠加生效。

### 9. 列表键盘流（P1）
- **方案**：在列表视图（无弹窗打开时）增加快捷键：
  - `Delete`：删除当前选中项（进入回收站，不走永久删除）；
  - `Ctrl` / `Cmd` + `A`：全选当前筛选结果；
  - `↑` / `↓`：在筛选结果间移动选中；
  - `Enter`：打开 / 编辑选中项。
- **验收**：上述快捷键在列表下生效；弹窗打开时让位给弹窗交互。
- **注意**：不得破坏现有 `Esc` 全局行为（已验证 `App.vue` 中 `Esc` 能关弹窗并清选择，保持不变）。

## 一致性与边界注意

- Issue 4 落地后，`AddEditModal` / `AddTagsModal` / `PickCategoryModal` 三处的"标签 / 分类选择"体验需要对齐。建议 `PickCategoryModal` 也补"新建分类"入口（与 `AddEditModal` 一致）；若本次时间有限，至少记录为后续项。
- 仅改动前端交互与样式，**不涉及 Rust 后端逻辑**。
- 现有"全选复选框 / Ctrl+Shift 多选 / 全局 Esc"等能力保留，不回退。

## 验收与回归

- 前端：`npm test`（vitest，含 `src/store/app.spec.ts`）全绿；`npx vue-tsc --noEmit` 零错误；`npm run build` 通过。
- 手动验证：逐条覆盖上方每个"验收"点。

## 不在本次范围内的已知项（记录）

- 列表虚拟滚动（超大量数据性能）
- 完整无障碍（ARIA / 焦点陷阱 / 菜单方向键导航）
- 弹窗自动聚焦、搜索快捷键、增强型 toast
- `PickCategoryModal` 新建分类入口（建议后续补）
